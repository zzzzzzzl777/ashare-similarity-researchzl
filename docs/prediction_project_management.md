# 短线 T+1 预测项目管理

## 项目目标

项目目标是建立可发布、可复验、可持续扩展的短线 T+1 方向预测流程。正式验收只看可部署口径，不用 research-only 结果包装发布能力。

当前发布门禁固定为：

- 高置信样本 T+1 方向准确率不低于 75%。
- Wilson 95% 下界不低于 75%。
- Brier Score 优于样本正例率常数基线。
- 高置信样本量不少于 10,000，或覆盖率达到预先登记的最低要求。
- 测试集只做一次最终验收，不能参与阈值选择、因子筛选、概率校准或样本过滤。

未达到以上条件时，结论只能标记为 blocked 或 research，不得产出 passed artifact。

## 数据闸门

所有进入训练或验收的字段必须先通过数据闸门：

- 明确数据源、抓取方式、交易日归属和披露时间。
- 确认在预测时点已经可知，不能使用 T+1 或收盘后才出现的信息预测同一日。
- 有可回放的历史快照或稳定缓存；没有历史快照时只能进入 research，不得进入正式 expanded 或 passed。
- 免费数据源的缺失、限流、口径差异和补齐速度必须记录到实验 manifest。
- 分钟线、竞价、涨停池、题材热度等增量数据必须独立缓存，并能按交易日落盘复验。
- 不允许伪造历史快照；无法证明当时可见的数据，一律按不可用处理。

## 验收流程

1. 数据准备：确认日线、分钟、竞价、真实涨停池等输入已经通过数据闸门。
2. 因子登记：新增因子先进入 `research`，说明来源、时点、风险和预期作用。
3. 探针实验：使用固定时间切分，训练窗口内再切验证集；测试集只做最终验收。
4. 阈值选择：只允许用训练窗口内验证段选择高置信阈值、方向侧和概率校准。
5. 发布判断：同时满足 75% 准确率、Wilson 下界、Brier 和样本量门禁后，才允许写入 passed 结论。
6. 全量拟合：只有 passed artifact 存在时，后续全局拟合才能读取该配置。

## 实验 Manifest 必填字段

每次实验必须保存 manifest，字段至少包括：

- `run_id`：唯一运行编号。
- `created_at`：运行时间。
- `owner`：实验负责人或执行线程。
- `purpose`：实验目的，例如 data_gate、factor_probe、release_gate。
- `dataset_version`：样本构建版本或缓存指纹。
- `trade_date_range`：训练、验证、测试交易日范围。
- `label_definition`：T+1 标签定义和涨跌方向口径。
- `sample_filter`：主板、活跃阶段、异动阶段、高换手/高成交/高波动等过滤条件。
- `feature_set`：因子集合名称，必须区分 research、expanded、passed。
- `factor_registry_snapshot`：因子登记快照或文件指纹。
- `data_sources`：使用的数据源和披露时点说明。
- `snapshot_policy`：历史快照、缓存和缺失处理策略。
- `model_config`：模型、特征选择、校准和阈值选择参数。
- `hardware_stage`：CPU/GPU 阶段说明，不能把 CPU 阶段描述为全程 GPU。
- `metrics`：全测试集指标、高置信指标、Wilson 下界、Brier 和基线 Brier。
- `decision`：passed、blocked 或 research。
- `known_limits`：本次结果的边界和不能外推的地方。
- `artifact_paths`：报告、特征缓存、模型和 passed artifact 路径。

## 当前已知瓶颈

- 真实涨停池覆盖偏低，历史快照不足时无法形成稳定可回放样本。
- 分钟线和集合竞价因子已有方向，但尚未可靠接入正式训练和验收链路。
- 当前日线和主观代理因子堆叠后，高置信准确率仍明显低于 75%。
- 2026-05-01 已补 `lockbox_ledger.jsonl` 门禁；正式 `final_unseen` 不能复用已经 research 观察过的 lockbox。
- 2026-05-01 已把分钟结构因子接入 `research` 训练矩阵；5 分钟缓存探路覆盖约 2026-02-09 至 2026-04-28，只能做近期 smoke，不能当三年正式训练输入。
- 扩大样本规模没有自动提升效果，说明主要瓶颈在信号质量和数据时点，而不是单纯样本量。
- 不能伪造历史涨停池、竞价或题材快照；没有当时可见证据的数据不能进入 passed 路径。
- 免费数据源存在限流、缺口和口径漂移，必须在 manifest 中显式记录。

## 下一轮优先级

P0：

- 建立真实涨停池和炸板池的可回放快照，优先解决覆盖率和交易日归属。
- 把分钟尾盘、早盘、成交分布、量价相关和日内波动接入训练样本。
- 补齐可回放分钟缓存，并在每轮 GPU probe 的 `feature_cache.intraday_cache_state` 中记录覆盖状态。
- 把集合竞价量比、竞价涨幅、竞价封单和竞价异动接入数据闸门。
- 为每次实验生成完整 manifest，并把 passed 写入路径锁定为唯一发布入口。

P1：

- 建立 research 因子晋级评审节奏，避免继续无约束堆叠主观日线代理。
- 对真实涨停池、分钟线和竞价因子分别做消融实验。
- 补充数据缺失率、覆盖率、披露时点和缓存指纹检查。

P2：

- 评估资金流、龙虎榜、题材热度、新闻和股吧情绪等外部数据的历史可得性。
- 只有当披露时间和历史快照可证明时，才允许进入 expanded。

## 发布前检查

- 是否存在 passed artifact，且来源是正式验收而非 smoke/research run。
- 是否所有训练字段都有数据闸门记录。
- 是否 manifest 记录了样本区间、特征集合、模型配置和指标。
- 是否没有用测试集调阈值、筛因子或做概率校准。
- 是否没有把缺少历史快照的数据包装成可回放数据。
- 是否当前结论明确说明 blocked、research 或 passed。
