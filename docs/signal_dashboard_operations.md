# Signal Dashboard Operations

## Building the Signal Cache

```bash
python -m ashare_similarity.cli build-signals
```

Options:
- `--frozen-candidates PATH` — Override frozen candidates JSON path
- `--force-rebuild` — Ignore existing cache and regenerate

### Prerequisites

- GPU with CUDA support (RTX 5090 recommended)
- Python packages: torch, xgboost, lightgbm, catboost, pandas, numpy, pyarrow
- Feature cache parquets (generated by prior gpu-prediction-probe runs)
- Frozen candidates JSON with valid run artifacts

### Expected Runtime

2-5 minutes for training all candidate models across both configurations.

### Output

```
{cache_root}/
  current.json
  {build_id}/
    signal_cache.parquet
    manifest.json
```

## Starting the Web Server

```bash
python -m ashare_similarity.cli serve
```

The server starts on port 8011. The signal cache is NOT loaded at startup —
it is lazy-loaded on the first API request to `/api/signals/v1/*`.

## Verifying the Build

1. Check status: `GET /api/signals/v1/status`
   - `ready`: cache loaded and validated
   - `not_built`: no cache found
   - `manifest_mismatch`: cache exists but doesn't match frozen candidates

2. Open dashboard: `http://localhost:8011/signals`

## Troubleshooting

- **503 on data endpoints**: Run `build-signals` first
- **manifest_mismatch**: Frozen candidates changed since last build; run `build-signals --force-rebuild`
- **Missing dependencies**: Install torch, xgboost, lightgbm, catboost
- **Feature cache not found**: Run the original gpu-prediction-probe to generate feature caches
