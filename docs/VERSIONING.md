# 版本策略

## 当前阶段

项目当前处于 `0.x` 阶段，目标是把本地离线检索、可恢复维护和 GitHub 交付质量做稳。

## 语义版本

采用 `MAJOR.MINOR.PATCH`：

- `MAJOR`: 会主动打破既有 CLI / API / 存储兼容性的版本
- `MINOR`: 新功能或可感知增强，尽量保持兼容
- `PATCH`: 缺陷修复、文档修正、非破坏性优化

## 在 0.x 阶段的兼容承诺

- Web 页面布局和文案可以继续优化
- CLI 输出字段允许在不破坏核心含义的前提下扩展
- 本地索引和缓存结构可能继续演进，但应在 `CHANGELOG.md` 写清楚
- 破坏性变化必须在发布说明里显式标注

## 代码版本 vs 数据版本

这个项目不仅有代码版本，还有本地数据工件：

- `DuckDB` 元数据
- `Parquet` 缓存
- `npy` / `manifest.json` 索引文件

后续如果出现需要迁移的存储格式变更，应在变更日志里单独标出“数据工件兼容性”影响，而不是只写代码版本号。
